# Accountable specialist recovery

Accepted manual or automatic specialist advice creates a durable recovery obligation in the existing owner/job/run recovery record. Receiving advice does not execute anything. The specialist supplies an observable recovery goal; the applying agent must adopt it or explain a supported alternative or rejection using an exact quotation from current browser evidence.

The parent records a normal tool/action and concrete repair intent with `respond_to_specialist`, then supplies the executable arguments once through that normal typed tool. The normal executor validates and durably records the actual operation; planning does not require a second nested copy of its argument schema. A fresh observation is required before `check_specialist_recovery`. Resolution requires a successful operation and a locally checked field value, page text, enabled control or URL path. An already-satisfied goal requires a targeted readback, rather than an unrelated click. Intermediate navigation leaves the obligation pending. Previously visited pages and repeated operations cannot claim progress. Ref changes do not turn the same observed target into a new operation.

Stale decisions, invalid quotations, private fields, failed operations and unsupported operations cannot clear the obligation. Two invalid accountability responses lead to an explicit unresolved stop rather than another reporting loop. A contradictory normal halt assessment can reopen the task for a different operation. Recovery state, operation history and pending verification survive in-run continuation. Current observation failures permit read-only reinspection.

Mandatory recovery turns use the immutable policy/candidate prefix and the fresh observation containing the durable obligation, actual result and recorded draft. Superseded browser plans stay in the audit transcript but cannot compete with the one required tool for this generation. Malformed checkpoint diagnostics retain returned tool names and text length without logging candidate content.

The parent refreshes and compares actual DOM evidence before and after consultation, including same-URL form transitions and wizard hash changes. Advice for a page that advanced asynchronously is discarded without creating an obligation. Ref-based goals bind to the observed field/action label, so reusing a short ref on a later wizard page cannot verify a different control.

Evidence quotations accept the same rendered field rows, options and refs shown to the parent, as well as the safe semantic view; semantic fingerprints remain independent of changing refs. Native JSON results are decoded before matching quoted values. Goals identify exact observed labels or refs and literal saved values. The specialist receives the parent's current mode restrictions, so advice and isolated helpers cannot introduce scripts or interactions unavailable to approved applications.

The existing spending meter, application approval, candidate evidence, authentication and uncertain-send rules remain authoritative. Recovery decisions do not receive completion-reserve funding for browser work. Helpers use the same live executor and cannot send or run scripts while the recovery remains unresolved. Budget completion and recording an already-attempted application's actual receipt are never trapped by the obligation.

Explicit inspection of a unique, visible, non-private typed cover-letter control now retains its real approved-text readback across wizard pages. A fill request or model assertion does not establish that proof. Subsequent changed/blank/invalid values, cancellation, Escape and direct URL navigation invalidate it. Ambiguous inspections cannot establish it. This repairs the missing evidence path that caused Treasury's final submission guard to reject an inspected inline letter.

When the native control has no HTML label, its current observed identity/ref must bind to exactly one non-private cover-letter field before that field's observed label can be used. A different or ambiguous control cannot borrow the label. The browser regression uses this markup rather than assuming a native label exists.

The verified native readback returned after a fill can establish the same proof; the requested text alone cannot. Operation matching normalizes documented targeting defaults (inferred target mode, exact text matching and an empty main-frame scope), while still rejecting changed targets, values, scope or submission intent.

Focused checks use scripted providers, isolated invalid-domain forms and fictional candidate data. They cover advice acceptance/alternatives, actual execution and verification, stale/repeated states, continuation, budget/uncertain-send boundaries and an approved letter inspected on an earlier wizard step followed by one fictional receipt-confirmed submission. No real model calls or employer applications are made by these checks.

An unresolved recovery protocol can end only as a technical skip, including in the exhausted-budget completion lane, never as Needs attention. Genuine missing candidate facts remain available through the ordinary securely captured-question path after recovery has been verified. Recording an already-attempted application's actual receipt remains available.
