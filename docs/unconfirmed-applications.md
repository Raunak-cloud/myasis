# Unconfirmed applications

A native Submit attempt without an employer receipt remains visible in application history as **Unconfirmed**. Job-board, direct employer-site and approved email orchestration retain these outcomes in the account's existing application store. Unconfirmed records block automatic duplicate sends and do not increment confirmed submission counts or consume a successful-submission slot. A technical stop before any possible send does not create an application record.

Captured letter, answer and resume metadata describe the attempt, rather than proving employer acceptance. Historical run outcomes and traces remain unchanged. Existing confirmed records are not replaced by later uncertain outcomes.

The candidate can report an interview invitation or rejection from the application details. That explicit report resolves delivery uncertainty and appends a separate human-outcome audit event. Updates are scoped to the authenticated owner, job ID and job board; legacy requests without a board are refused if ambiguous. Application content and original application time remain unchanged. Clearing the outcome does not erase the earlier delivery confirmation.

Historical restorations require exact owner/job/source evidence and an explicit human confirmation. They are audited separately as owner-reported outcomes, without manufacturing an employer receipt or rewriting the original run.
