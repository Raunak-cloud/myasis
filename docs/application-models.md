# Application models

Admins can choose **Celeris Magnus**, **MiniMax M3.1**, or **DeepSeek V4.1 Flash** on Apply. The choice is saved immediately and applies to the next run. An operator can also select a model in a single admin request without changing saved preferences. Ordinary accounts always use Celeris, including when an old saved preference or a client override requests another provider. Model identities keep fit and draft caches separate.

MiniMax uses `minimax/minimax-m3.1-flash` through OpenRouter. The admin-only `/forms` lab also offers both models. Configure `OPENROUTER_API_KEY` in Admin → Config → Models. The server rechecks the active account's admin status and selects credentials before spawning a worker. API keys never go into account settings or the dashboard bundle. An unavailable selected provider fails explicitly; it does not silently fall back to a different model.

DeepSeek uses `deepseek/deepseek-v4.1-flash` through the same OpenRouter key. Job review, ranking, application and specialist calls all use its own identity and charges. It starts at high reasoning, uses low for reduced-effort recovery, omits temperature (ignored in thinking mode), and defaults to screenshots each decision turn. The provider catalogue supplies its supported effort levels, tool serialization and fallback token rates. The tool adapter preserves the same canonical argument validation and candidate confirmation controls used by the synthetic comparison. One-time operator trials retain normal run history, ownership checks, saved search criteria, duplicate checks and limits.

Both models run the same application loop, receive the same offered browser tools, and use the same recovery and candidate-confirmation rules. Read-only specialist consultations use the selected application provider and share the parent's spending meter. OpenRouter reasoning blocks are retained unchanged across tool turns. Provider retries only regenerate replies; they cannot replay browser actions. MiniMax uses DOM/HTML observations during ordinary work, with a fresh screenshot on execution errors, stalled recovery or an explicit visual request. Historical images are removed on the next DOM-only turn. Celeris retains its every-turn screenshot default; the MiniMax policy also applies to the forms lab despite legacy screenshot settings.

Authentication tools declare their input-selection alternatives in the shared schema: credential filling requires `targets` or `refs`; code entry requires `targets`, `ref` or `refs`. Empty selections are rejected before browser or mailbox work. Rejected arguments are failed tool calls in the admin diagnostics and recovery flow, and cannot count as successful browser mutations. The agent still chooses every input and repair.

OpenRouter's `usage.cost` is the billing source when present. Otherwise the meter uses published non-discounted token rates; absent usage reserves estimated input and the requested output allowance and records the final charge as unknown. Every generation, including an incomplete reply, counts toward the same per-application budget. These amounts are USD; Celeris and OpenRouter have separate account balances.

For a fair synthetic comparison, keep the form seed, fictional candidate, tools, screenshots, base/progress budgets and time allowance identical. Give each attempt a unique email challenge namespace to prevent old verification emails or delivery idempotency keys from contaminating a retry. Report independent employer receipts, elapsed time, all model charges, tool errors and successful recoveries. A single paired trial is a smoke comparison, not a general reliability benchmark.

Candidate-evidence searches rank exact-token passages with BM25 and return only matches. Exact document IDs and empty-query pagination retain access to complete sources; a search miss is never treated as proof that a fact is absent. This keeps generic policy language and unrelated saved answers from consuming the first response. References: [BM25](https://www.elastic.co/blog/practical-bm25-part-2-the-bm25-algorithm-and-its-variables), [tool response design](https://www.anthropic.com/engineering/writing-tools-for-agents).

Repeated identical evidence responses on an unchanged form now enter the shared recovery flow, including alternating queries. The agent receives a pagination/reuse advisory, deeper reasoning and an available bounded specialist consultation. Reads are not browser progress or budget credit; new evidence pages and genuine form changes remain valid. No form action, answer, submission or fixed step limit is imposed by this detection. MiniMax's core instruction explicitly prioritizes advancing required fields and pages toward an observed receipt instead of repeatedly researching already-read evidence.
