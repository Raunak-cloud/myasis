# Applying agent

Magnus owns answer selection, factual comparison, document choices, browser
actions, diagnosis, repair and employer-receipt interpretation. The matcher
owns the approved fit and known-duplicate decision. No second reviewer model
approves an application.
Explicit selections and approved matches receive one suitability instruction;
only unreviewed work receives the fallback matching policy. Source review uses
the canonical saved-form reader; raw wizard observations cannot overwrite a
reviewed selected tag with its empty autocomplete search text.

Owtomate transports native browser operations, fresh screenshots, scoped
candidate evidence and durable progress. Locators resolve current elements;
writes remain strict and read-only inspection can label several matches.
Browser observations and an action audit are not proof of employer acceptance.
Checkpoint instructions retain the same fresh browser observation and its
screenshot through transcript compaction. A newer browser observation without
a picture retires the earlier picture, so stale images cannot imply new state.
Transcript pressure uses a text estimate plus an image-token reserve, never
base64 byte length. Actual provider usage remains the billing source. Native
inspection collapses markup indentation in metadata without changing values.
Script inspection intent does not execute a recovery plan or earn spending;
unlabelled scripts remain potentially mutating, and all script permissions and
marked-send approval remain independent of this bookkeeping.

`application-policy.ts` defines the applying policy once. Ordinary turns use
medium reasoning. Failed interactions and recovery retain deeper reasoning
through the actual repair and its fresh result assessment. The agent can ask a
bounded read-only specialist for advice within the same spending budget.

`application-readiness.ts` replaces the date-only checkpoint. Before preparing
or sending, the same applying agent reviews consequential answers, dates,
consent, the vacancy, letter and attachments with identifiable candidate sources.
The tool records the decision, never infers an answer or performs a send.
Corrections invalidate readiness. Held sends are not queued or replayed.
Historical wizard fields remain explicitly unconfirmed observations, because
they may belong to cancelled editors. The agent must inspect saved entries.

Keep account isolation, Semi auto confirmation, confirmed-duplicate protection,
application allowances, hCaptcha skipping, spending limits and the whole-run
watchdog outside the agent's discretion. Browser/provider operations have
bounded timeouts; there is no separate application elapsed-time cutoff.

Focused browser fixtures use scripted model replies and test event handling,
readbacks, corrections, missing sources, consent/approval boundaries, receipts
and recovery sequencing. They do not measure autonomous model accuracy. Live
attempts separately report receipt evidence, all failures and known AI cost.
Neither a self-review record nor five live attempts establishes perfect accuracy.
