# Application model selection

Administrators can choose **Celeris** or **Claude Haiku 5.5** on the Apply dashboard. The selection is saved per account and captured for the next run. It covers screening, ranking, CV choice, letter drafting and editing, answers, browser control, sign-in, recovery, actual-form verification, duplicate decisions, receipt verification and post-run search-term renewal. A provider failure never changes the selected model.

The server rechecks the account's administrator status and emits `APPLICATION_AI_MODEL`, `APPLICATION_AI_ADMIN_ENABLED` and `APPLICATION_AI_OWNER_ID` after caller overrides. Haiku additionally checks that `DATA_DIR` is that owner's directory. Non-administrator runs use Celeris and retain their existing rewriting service. Shared dashboard helpers use an asynchronous request scope rather than changing `process.env`.

Haiku requires server-side provider credentials, configurable in Admin settings. The native browser-toolset application path requires `ANTHROPIC_API_KEY` and direct Claude API access: the OpenRouter compatibility probe rejected that dated toolset. `OPENROUTER_API_KEY` remains supported for ordinary Haiku Messages calls without the browser toolset. Keys are never sent to the dashboard's browser. A missing or incompatible route stops with a setup message; it does not silently substitute custom browser tools or Celeris. Credentials and model do not change during a run.

## Haiku protocol

`agent/haiku.ts` uses native Messages: direct `claude-haiku-5-5`, or `anthropic/claude-haiku-5.5` through OpenRouter's `/api/v1/messages`. It uses native `tool_use`/`tool_result` blocks and native structured output. Effort follows the reasoning tier requested by each caller: short checks without reasoning use low effort and thinking off; reasoning calls use medium adaptive thinking, or high when they request deeper reasoning. The browser conversation stays at one medium level. Tool conversations use automatic caching. A one-off prompt caches only its trusted prefix (the text before the first `<untrusted` data block), and only once that prefix has repeated, so unique prompts never pay for cache writes. It omits Magnus chat templates and unsupported sampling parameters. Original JSON schemas are validated with Ajv, including constraints moved to descriptions for provider compatibility.

Custom grounding helpers remain available alongside the native browser toolset. A stable subset of compatible closed custom schemas uses `strict: true`, within the native limits of 20 strict tools, 24 optional parameters and 16 union parameters; structured-output schema parameters share that budget. Remaining custom tools are non-strict and retain local Ajv validation. The native browser declaration has no `name`, `strict`, or custom input schema. The exact wire toolset, enabled native members and definition fingerprints are stored with native assistant history and replayed unchanged. Definition changes or legacy native history without this metadata stop with a fresh-conversation requirement; this is intentionally fail-closed, not an automatic resume. A first-turn custom strict-schema incompatibility can retry once without strict mode for that conversation only. It never disables strict mode process-wide, removes the native browser declaration or changes definitions underneath signed history.

Provider errors expose fixed typed categories and safe request identifiers, not raw response text or private payloads. Explicit grammar-compilation throttles, including HTTP 400, receive one bounded cooldown using `Retry-After` when present, otherwise approximately 60 seconds, within the original request deadline. Ordinary HTTP 400 errors do not retry. A cooldown preserves the exact request body and strict toolset; it never falls back to Celeris.

Haiku's browser controller declares Anthropic's actual `browser_toolset_20260801`; Anthropic supplies its member definitions and Owtomate executes them in its own browser. Calls are distinguished by `(toolset_name, name)`, so a native `browser.read_page` and a same-named custom helper remain separate. Native tool results echo `toolset_name: "browser"` and retain structured text, image and `browser_state` blocks. Tab state is an inventory of the actual tabs, with stable IDs; screenshots use viewport pixels. Only executor-supported members are enabled. Browser JavaScript execution and unimplemented diagnostics stay disabled; file uploads require a task-scoped staged-file allowance.

Browser batches execute in order. After the first failure, remaining calls receive error results rather than executing on an unexpected page. Earlier native thinking blocks and tool results remain unchanged; context rollover starts a fresh conversation from verified executor state, including any possible submission. Candidate grounding, actual-form checks, duplicate protection and explicit receipt checks remain executor responsibilities. Declaring the native toolset does not supply a remotely hosted browser or establish that the application is reliable without testing.

Cost records use actual provider charges when available. Direct native usage is explicitly estimated at published rates. Delayed OpenRouter billing remains partial; a usage-based estimate enforces the application budget without pretending it is an invoice.

Archived comparison harnesses and test results are not selectable dashboard models.
